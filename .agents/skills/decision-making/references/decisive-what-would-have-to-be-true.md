# Decisive: What Would Have To Be True?

## When to Use

Trigger when multiple options are competing and people are advocating:

- Add, trim, hold, or exit all have defenders.
- Two SMB targets or product directions are hard to compare.
- A preferred option is being sold too hard.
- Dissent feels personal or politically costly.
- The user needs a neutral way to compare options.

Don't trigger for: one thesis with no alternative. Use `duke-wanna-bet-belief-vet` first.

## The Framework

### Core Thesis

The question "What would have to be true for this option to be the best choice?" changes the conversation. Instead of arguing for or against a proposal, each option gets truth conditions that can be tested.

### Option-Specific Conditions

Every option has a set of facts that would make it right. Name them explicitly.

### Safe Dissent

Dissent becomes less personal when the group is testing conditions, not attacking people.

### Evidence Gaps

The best next step is often not choosing. It is learning which truth condition is least certain and most important.

### Disconfirming Questions

Ask questions that can reveal problems. Make them open enough that people can answer honestly.

## How to Apply

1. **List live options.** Include do-nothing if it is real.
2. **Write truth conditions.** For each option, finish: "This is best if..."
3. **Rank conditions.** Mark each as known, uncertain, or assumed.
4. **Find cruxes.** Identify conditions that would change the decision if false.
5. **Write disconfirming questions.** Ask what problems, risks, or missing facts could break each option.
6. **Assign evidence tests.** Pair each crux with a source, ooch, outside view, or stock review.
7. **Decide next move.** Choose, test, defer, or eliminate options.

## Output Format

```markdown
## What Would Have To Be True?: {decision}

Options:

| Option | Would be best if... | Confidence | Evidence needed |
|--------|----------------------|------------|-----------------|

Crux conditions:
Disconfirming questions:
Next evidence tests:
Current leader:
Why:
```

## Common Failure Modes

- **Advocacy mode.** Each side argues instead of naming testable conditions.
- **Vague truths.** "This works if the company executes" is not testable enough.
- **Do-nothing omitted.** Holding cash, keeping the status quo, or passing is usually an option.
- **False consensus.** Everyone agrees at the slogan level but differs on the crux facts.
- **No next test.** The table is useful only if it changes evidence-gathering.
